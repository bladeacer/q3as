# Changelog v0.6.0

Not the whole log: see the [changelog index](index.md) for every version and
the [results index](../results/README.md) for the measured numbers.

No evaluation run has been made for this version yet, so there is no
`result-v0.6.0.md`; nothing here quotes new benchmark numbers. This version
changed what the pipeline extracts from the sources it already has, and how
much of the synthetic contract curriculum survives the build. No new data
source was added; every turn comes from the cached repositories
[data-provenance](../data-provenance.md) already lists.

**The training set changed**, from 78,166 to 79,173 turns, and the mix moved
toward the shapes the evaluation scores:

| Kind | v0.5.0 | v0.6.0 |
|---|---|---|
| `contract_synth` | 177 | 708 |
| `lab_pair` (new) | 0 | 129 |
| `toolchain_qa` | 11 | 17 |

Runs on the two datasets are not comparable for loss. The intended effect is
on the generation metrics: these turn kinds are the ones shaped like the
benchmark (declaration in, completed unit out; contract in, repaired unit
out; toolchain question in, workflow answer out).

## The contract curriculum survived dedup, then scaled 4x

[v0.5.0](v0.5.0.md) grew the gnatprove-verified contract families to cover
every eval proof blocker, but the build then threw most of that work away:
the AST-structural cap (10 per alpha-renamed shape) cannot tell a deliberate
curriculum from extractor spam, and within a family the write-turn and
fix-turn answers share one renamed shape. At the shipped cap, more than half
of a scaled run was cut per family.

`contract-synth:` groups are now exempt from the cap, exactly like prose
turns: the per-family shape repetition is the point, every instance is
prover-verified before it trains, and the family is a fixed budget (24
instances per template) rather than an unbounded extractor, so the
family-balance risk the cap exists for does not arise. Exact duplicates
still drop.

The instance budget rose from 60 to 240 (`--limit` on
[`scripts/gen_contract_mutations.py`](../../scripts/gen_contract_mutations.py)),
which verified 708 turns in one 9.5-minute gnatprove run. The stage is
fingerprinted, so that cost is paid only when a template or the limit
changes. All ten families stayed balanced at 72 turns each; 24 more in
`init_default` reflect its extra body-completion turns.

## Labs: the training material's prompt/answer twins became completion turns

Each AdaCore training-material lab ships two parallel source trees:
`prompt/` (the skeleton the student starts from) and `answer/` (the worked
solution), file names matching one to one, with the lab's task text in the
surrounding RST. This is the exact format the ada-eval benchmark scores -
an incomplete unit in, a completed unit out - and none of it reached the
dataset before: the documentation path reads only RST/Markdown fences, never
the lab's `.ads`/`.adb` files.

The builder now walks the doc roots for `prompt/` directories with an
`answer/` twin, pairs the files, and emits one completion turn per differing
Ada file pair ([`discover_lab_pairs`](../../data/processing_scripts/build_dataset.py)
and `build_lab_pair_turns`). Sixty-nine labs ship twins; 47 labs yield 129
turns after the identical-file and non-Ada skips. All turns of one lab share
a split group, so a prompt is never separated from its answer.

## The skills repo's proof workflow docs are now taught

Only the five `SKILL.md` files of the AdaCore skills repo were ingested; the
68 markdown files under `references/` were never read, and the ones that
matter most for the eval - `gnatprove/references/proof/` (triage of unproved
checks, hint strength ordering, refactoring for proof, overflow patterns,
the proof workflow) - live deepest in that tree. Three defects stacked up:

- the reference loader used a non-recursive glob, so nested references were
  invisible;
- the per-reference cap (6,000 chars) cut the larger guides mid-document,
  hiding the exact sections the new questions anchor on;
- the QA question table had no proof-workflow questions at all.

References now load recursively, the cap covers the largest guide whole
(24,000 chars), and six proof-workflow questions were added. Toolchain QA
went from 11 to 17 turns, including triage steps for exactly the failure
kinds the eval reports (`VC_OVERFLOW_CHECK`, unproved postconditions).

## For the next run

Nothing in the training or evaluation code changed in this version beyond
the extraction paths above; the guard, splits, and defect families are
untouched (`make check-integrity` clean, `make validate-defects` clean). The
metrics to compare against v0.4.1 are the prove blockers and the per-dataset
build/test table.
