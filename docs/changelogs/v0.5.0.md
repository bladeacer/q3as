# Changelog v0.5.0

Not the whole log: see the [changelog index](index.md) for every version and
the [results index](../results/README.md) for the measured numbers.

No evaluation run has been made for this version yet, so there is no
`result-v0.5.0.md`; nothing here quotes new benchmark numbers. What this
version changes is what the training data teaches, and whether
`make update-sources` actually updates anything.

**The training set changed**, from 77,758 to 78,166 turns. The delta is
small in count and pointed in kind: the gnatprove-verified synthetic
contract turns more than doubled, from 81 to 177, and every new turn
targets a proof blocker the v0.4.1 evaluation measured. The sources were
also refreshed to their current upstream commits, which shifts the
extracted counts around the new content. Two defect turns that claimed a
compiler message GNAT does not emit are gone (see the last section). Runs
on the two datasets are not comparable for loss, and the point of the
change is the next generation run's prove numbers.

## Synthetic contracts now cover every eval proof blocker

The v0.4.1 evaluation left the fine-tuned model at 0/19 SPARK samples
proved. The blockers, in order:
`VC_OVERFLOW_CHECK` x8, `UNINITIALIZED` x4, `VC_POSTCONDITION` x3,
`VC_RAISE` x2, `DEPENDS_MISSING` x2. The synthetic contract generator
([`scripts/gen_contract_mutations.py`](../../scripts/gen_contract_mutations.py))
already existed and already verified everything with the real
`gnatprove`, but it carried five template families - four of them
overflow-guard shapes, which the model was already learning from 24,549
`ast_defect` turns. Nothing in the corpus taught initialization, raise
guards, loop invariants, or `Global` flow contracts.

The generator now carries ten families, at least one per blocker:

| Family | Teaches | Eval blocker |
|---|---|---|
| `guarded_increment`, `guarded_subtract`, `even_halve`, `clamp_range` | `Pre` contracts that bound arithmetic before it runs | `VC_OVERFLOW_CHECK` |
| `init_default` | an `out` parameter assigned on every path, `Post` stating what was stored | `UNINITIALIZED`, `VC_POSTCONDITION` |
| `raise_guard` | a `Pre` that makes the `raise` impossible | `VC_RAISE` |
| `loop_sum`, `loop_max_array` | a floating `Loop_Invariant` tied to the processed prefix, plus the `Long_Long_Integer` widening that discharges the accumulator's overflow checks | `VC_OVERFLOW_CHECK` on loops, `VC_POSTCONDITION` |
| `swap_depends` | an explicit `Depends` flow contract | `DEPENDS_MISSING` |
| `global_counter` | a `Global` aspect over package state, with the precondition reading that state | `DEPENDS_MISSING`, `VC_OVERFLOW_CHECK` |

Every strong form is verified proved, and every wrong variant is verified
not proved, by gnatprove 16 at `--level=1`, exactly as before; the
verification gates did not loosen. What changed:

- The default instance budget rose from 30 to 60, and each family can now
  emit up to four turn kinds: write the contract, explain why it
  discharges, complete a body under a spec (the
  `init_default` family, where the lesson lives in the body), and repair
  a machine-verified broken contract. The `init_default` repair turns
  show the "add `Pre => N > 0`" fix that the v0.4.1 blockers call for,
  with the explanation of why restricting inputs is the right repair.
- The declaration extractor kept only the text up to the first semicolon,
  which cut every multi-parameter declaration at its parameter list
  (`procedure Fill (R : out Natural;`), in the emitted contract-writing
  turns. It now scans to the semicolon at parenthesis depth zero, so
  quantified postconditions and `Depends` tuples survive. The generated
  Ada in these turns is also verified per family against gnatprove before
  release; the loop templates were written to prove at `--level=1`
  without solver aids.

This is a data change, not a pipeline change: the builder, the guard,
splits, and the dedup logic are untouched, so the new turns flow through
the same verification (the eval guard reports 394 blocked signatures, no
eval content in any split) and land in the same splits by group.

## Two defect pairs stopped claiming messages GNAT does not emit

`make validate-defects` compiles every dataset defect pair with the real
GNAT and checks the claimed message. Two snippets failed the contract:

- a `typo` pair whose misspelling landed on a formal parameter in a
  multi-line subprogram profile. The spec must stay conformant with the
  body, so GNAT leads with "not fully conformant" and "name does not
  match", never the claimed "undefined".
- a `nonexistent_call` pair whose truncated call name collided with a
  real declaration (the call-site pattern also matches a spec
  declaration line), so GNAT resolved the name and reported a missing
  body instead of "undefined".

Both injectors now skip such candidates (the typo guard walks back over a
profile's continuation lines; the call corruptor rejects declaration
lines and truncated names defined anywhere else in the snippet), and the
family validates clean end to end. These two turns were teaching a
message the compiler never produces.

## make update-sources updates sources

It did not. The check side worked: `make check-sources` compared recorded
commits with upstream and named what moved. The update side then
re-fetched nothing, because the fetch path short-circuits on the cache
before it ever consults why the entry was selected. On a cache where
every repository was fetched before commit recording began, `--update`
reported ten repositories needing a re-fetch and re-fetched zero. The
same defect made `--refresh` a no-op for any entry already cached.

The fetch path now takes the set of repositories to force, and both
update modes pass it. A side effect of testing this end to end: the
GitHub REST API quota ran out mid-run, which exposed a second defect.
The commit recorded per cache entry came from that same quotaed API, so
a quota-limited run recorded `commit: null`, left the entry untracked,
and guaranteed that the next `--update` re-downloaded everything, over
and over, for as long as the quota stayed gone. Commits are now resolved
through the git smart-HTTP endpoint (`git ls-remote`'s URL, no hourly
quota) with the REST API kept as a fallback.

All ten cached repositories now record upstream commits, and
`make check-sources` reports every one current.

## For the next run

Nothing in the training or evaluation code changed in this version. The
expected effect of the data change is exactly on the metric that has not
moved: SPARK proofs. The blocker histogram to compare against v0.4.1 is
`VC_OVERFLOW_CHECK` x8, `UNINITIALIZED` x4, `VC_POSTCONDITION` x3,
`VC_RAISE` x2, `DEPENDS_MISSING` x2.
