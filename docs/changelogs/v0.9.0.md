# Changelog v0.9.0

Not the whole log: see the [changelog index](index.md) for every version and
the [results index](../results/README.md) for the measured numbers.

This version is the last harness fault that costs samples, plus the reporting
rule that makes the distinction the v0.8.0 analysis asked for permanent: every
number states the split between the samples the model changed and the samples
it echoed. It builds the scope [`plan.md`](../../plan.md) carried for v0.9.0;
that file now holds the v0.10.0 scope, and the extraction track it inventoried
is carried there unchanged. No data source was added, and none was needed:
every turn still comes from the cached repositories
[`docs/data-provenance.md`](../data-provenance.md) lists, and the dataset is
unchanged from v0.8.0.

## A dropped `File:` entry must never be written into the target

Every ada-eval sample targets a spec (`.ads`) file. The v0.8.0 run had two
samples, `char_count_1` and `char_count_2`, that failed BUILD for a routing
mistake rather than for wrong Ada: the model replied with a single
`File: main.gpr` entry, `parse_generated_files` dropped it as outside the
target directory, and then fell through to the single-block fallback, which
wrote the fenced block at the target path. The project's `main.gpr` text
landed in `src/string_utils.ads`, and both samples reported
`subprogram_not_found` on the prove side. The two replies were
byte-identical.

The fallback chain now fires only when the reply carried no `File:` header at
all:

- every header match is collected, and whether any header matched is noted
  regardless of whether the path survived `_safe_source_path`,
- entries next to the target directory are still the overlay, unchanged,
- otherwise, if any header matched, the overlay is empty and the warning names
  the paths that were dropped and the target it left untouched,
- otherwise (no header at all) the existing chain runs: fenced block at the
  target, a `package body` block routed to the sibling `.adb`, raw text at the
  target.

A reply that addressed files but named none of them usably now leaves the
project exactly as shipped, so it scores as the base project instead of
breaking one. Deliberately unchanged: the v0.8.0 body routing, an explicit
`File:` entry winning over routing, and `reply_format` (a reply that names
`main.gpr` still counts as `file_blocks`, which is accurate; the model did use
the contract).

`tests/test_generate.py`: `test_absolute_path_rejected` and
`test_non_source_suffix_rejected` now expect an empty overlay, their names
kept; `test_all_entries_dropped_leaves_the_project_alone` pins the
`char_count` shape; `test_headerless_reply_still_falls_back` pins the three
fallback steps so the gate cannot silently remove the routing repair; and a
sidecar test asserts the dropped reply records `changed_files: 0`.

## Every report states the changed and unchanged split

Most ada-eval base trees already contain a body for the target subprogram and
already compile. A reply that echoes its input therefore collects BUILD and
TEST for the *base* project, which is how 12 of the v0.8.0 run's 15 builds
were inherited rather than earned. One implementation, in
[`eval/ada_eval_common.py`](../../eval/ada_eval_common.py):

- new `split_tally_by_changed_files(eval_results_dir, meta_path)` returns
  `{"edited": <stats>, "unchanged": <stats>}` from the same `empty_stats`
  buckets as the whole-run tally, joining per-sample results to
  `generation_meta.json` on the sample name. The per-file walk and the result
  classification moved into shared helpers (`iter_result_samples`,
  `tally_result`), so the split cannot disagree with the total about which
  files count or how a malformed line is treated. A run with no sidecar, a
  sidecar nothing joins, or a sample with no usable `changed_files` returns
  nothing usable, so older versions render as *not recorded* rather than as a
  zero that reads like a measurement.
- `scripts/gen_eval_report.py` stores `by_change` per model, renders a "Samples
  the model changed" table in every per-version report (both models, samples,
  build, test, proved, `n/a` through the existing `_fmt_pct(None)` path when a
  group was not recorded), and adds two rows to the cross-version table:
  "No-op replies (FT)" and "Build on edited samples (FT)".
- `eval/baseline_eval.py` prints `Build split: 15/19 (3 of 4 changed, 12 of 15
  unchanged)` beside the reply-format line.

The open decision from [`plan.md`](../../plan.md) is resolved in favour of
keeping both rows in the cross-version table with `n/a` for older versions:
the no-op count exists for v0.8.0 (13, stored in its
`reply_shapes.untouched`), and build-on-edited cannot be recovered for any
earlier version, so that row starts at v0.9.0. A row that says `n/a` for every
version but the current one is the honest record of when the split became
measurable, which is the point of the table.

`aggregate_eval_results` and the split were verified to partition the same
results (test totals and numerators add up), and the five historical reports
under `docs/results/` were re-rendered from their stored data files, so the
generated-file test stays honest about what was hand-edited. Each of them now
reads *not recorded* for the split, which is what those runs measured: the
v0.8.0 split is documented in
[`docs/eval-analysis-v0.8.0.md`](../eval-analysis-v0.8.0.md) because that run's
sidecar was read before it was overwritten.

## Publishing

`make bump-version PART=minor` moved 0.8.0 to 0.9.0 across
[`alire.toml`](../../alire.toml), `alire-dev.toml`, `alire-ast.toml` and
[`pyproject.toml`](../../pyproject.toml); two tests in
`tests/test_reporting.py` fail if those ever disagree.

**This is not a pure re-score of the v0.8.0 adapter.** The plan expected one:
the harness fix, re-run over the same adapter. The v0.8.0 checkpoint was not
retained on the machine that produced this version, so the v0.9.0 numbers come
from a full run - the same dataset, the same 500-step budget, a freshly trained
adapter, then `make generate eval-pipeline eval eval-report`. Two consequences
are worth stating plainly:

- the adapter differs, so a difference against v0.8.0 is not attributable to
  the harness alone. The harness effect is still exactly measurable on the two
  `char_count` samples, whose v0.8.0 replies are byte-identical and were
  scored in this run as no-ops;
- sampling is seeded (42) but CUDA kernels are not bitwise deterministic, so
  even the same adapter would not reproduce a run to the digit.

Keeping an adapter per version is what would make the next harness fix a
measured delta instead of an argument. It is scoped in
[`plan.md`](../../plan.md) for v0.10.0.

## Scoped, not built

[`plan.md`](../../plan.md) still carries the measured inventory of what no
extractor reads, ordered by value: write-shaped turns for the evaluation prompt,
unit-test turns from the test harnesses already in the cache, the Ada 83
conformance suite as error-diagnosis turns, ~10,000 unparsed documentation
sections, AdaDoc contract-documentation turns, `.gpr` build-configuration
turns, and the `training_material` Ada that no builder reaches. Its counts
were re-measured against the current cache while this version was built; see
the same file for the corrected numbers.

None of it is built here, and none of it may ship without `make
check-integrity`, `make validate-defects` and a result file to compare against.
