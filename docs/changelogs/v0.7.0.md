# Changelog v0.7.0

Not the whole log: see the [changelog index](index.md) for every version and
the [results index](../results/README.md) for the measured numbers.

The evaluation run for this version is
[`result-v0.7.0.md`](../results/result-v0.7.0.md). This version
finishes the extraction-quality work started in
[v0.6.0](v0.6.0.md): every remaining source is read, and the prover, not the
extractor, decides which real SPARK code trains. No new data source was
added; every turn comes from the cached repositories
[data-provenance](../data-provenance.md) already lists.

**The training set changed**, from 79,340 to 80,262 turns (train 72,105 /
val 4,071 / test 4,086). The delta is small in count and pointed in kind:

| Kind | v0.6.0 | v0.7.0 |
|---|---|---|
| `spark_verified` (new) | 41 | 568 |
| `lab_pair` | 252 | 252 |
| `assurance_qa` (new) | 5 | 5 |

Runs on the two datasets are not comparable for loss. The intended effect is
on the generation metrics, and above all on the prove blockers: 568 real
SPARK2 subprograms that gnatprove discharged are turns the model has never
seen.

## Prover-verified turns from all 16 SPARK2 trees

The Ada-Algorithms monorepo ships 16 `SPARK2` topic trees whose READMEs claim
proof friendliness, and [v0.6.0](v0.6.0.md) mined two of them (`sorting`,
`graphs`) into 41 verified completion turns. The tool was
`DEFAULT_SOURCES`-limited to those two paths.

It now globs every `<topic>/SPARK2` tree and takes each discovered unit
(no `--limit` ceiling): 577 standalone spec/body pairs, wrapped in a
synthetic package and proved in batches of 8 exactly like the contract
curriculum. **568 units proved** (400 of them carry contracts) and 9 did not,
so they were dropped. The 73 gnatprove batches take about 30 minutes on 16
cores; the stage is fingerprinted, so that cost is paid once per source
change.

The dropped units are the point of the exercise: they are units whose proof
obligations the prover could not discharge, which is exactly the class of
turn that taught the model to claim proof it does not have.

Two defects in the tool were fixed on the way:

- **`subprocess.TimeoutExpired` killed the run.** The batch guard caught
  `(TimeoutError, FileNotFoundError, OSError)`, and
  `TimeoutExpired` is a `SubprocessError`, not an `OSError`. One heavy batch
  (matrices, 600 s) therefore aborted the whole run after 20 minutes of
  proving. A timed-out batch now returns "not proved" for its units: the
  partial summary of a killed run cannot be trusted, so the batch is dropped
  rather than half-verified.
- **The source label lost the topic.** With one tree there was
  `Ada-Algorithms:SPARK2/<file>.ads`; with sixteen, two topics can carry the
  same file name, so the label is now
  `Ada-Algorithms:<topic>/SPARK2/<file>.ads` and says where the unit came
  from. Progress logging (a rate and an ETA over the 73 batches) keeps a
  30-minute stage from reading as a hang.

## Lab turns now explain the solution as well as complete it

[v0.6.0](v0.6.0.md) added the labs' `prompt/`/`answer/` twins as completion
turns: 129 completions from 47 labs. Nothing taught the model to *describe*
the change it had just made.

Each differing pair now emits a second turn in the same split group: the
skeleton and the solution go in, and an answer derived from the **diff only**
comes out (the subprograms the solution introduces, the line count against
the skeleton, and the first added statement when the diff has no subprogram
boundary). 123 explanations, 252 `lab_pair` turns in total. Deriving the
text from the diff is what keeps it factual: nothing is asserted that the two
files do not show. The quoted first statement is stripped of its
unified-diff marker, so no explanation trains on a leading `+`.

## The Platinum repos' compliance documentation became assurance QA

The SPARK Platinum sources (Ada_CRDT, adacovex) document *how a codebase
reaches and stays at Platinum* under `docs/proof`, `docs/compliance`,
`docs/usage`, and `docs/archive`: the assurance ladder with its per-level
criteria, the zero-justification doctrine, the skip taxonomy, the proof
ledger format, and the CI gate. None of it is source code, so no extractor
saw it, and the evaluation's proof failures are exactly the failures this
process knowledge prevents.

Five questions now anchor on the sections that state each practice, and the
answer is that section of the documentation, STE-cleaned. The loader
(`load_spark_assurance_docs`) reads only those four `docs` subtrees and only
when they exist, so the turn count does not depend on which optional repo was
fetched.

## One answer-chunking bug that truncated tables and leaked headings

Answers read out of documentation (`_extract_answer_chunk`) started at the
*end* of the anchor match. Three anchor shapes, three wrong starts:

- a table anchor matched only the first columns
  (`\|\s*Level\s*\|\sCriter`), so the assurance answer opened with the
  fragment `ion | Status |` in front of the ladder;
- a heading anchor matched the heading text only, so the answer opened with
  the tail of the heading line (the gnatprove triage answer opened with
  `— Choose Your Path`, an em-dash that STE forbids anyway);
- a prose anchor cut the first sentence in half ("person accepted with a
  written argument. A justified check is ...").

The chunk now starts on the line of a table row, after a heading, and at the
anchor phrase in prose. Seven unit tests cover the three shapes, the
keyword fallback, and the next-heading bound. Two of the 17 toolchain QA
answers changed as a result, both for the better.

## For the next run

Nothing in the guard, the splits, or the defect families changed
(`make check-integrity` clean, 406 tests pass, `make lint` clean). The
metrics to compare against v0.4.1 are unchanged in shape: the prove blocker
histogram, and the per-dataset build/test table.

## The measured result: the run went the other way

| Metric | v0.4.1 | v0.7.0 |
|---|---|---|
| Fine-tuned build | 16/19 (84.2%) | 10/19 (52.6%) |
| Fine-tuned test | 11/19 (57.9%) | 8/19 (42.1%) |
| Proved | 0 | 0 |
| Prove errors | 3 | 9 |
| Test loss | 0.2242 | 0.2024 |

The base model held its ground (build 7, test 5, against 8 and 5 on the same
19 samples), so the drop is the fine-tune, not the benchmark or the harness.
Held-out test loss improved, so this is not a worse-fit adapter either.

The cause is the answer **format**, and it is countable. The evaluation asks
for one `File: <path>` entry per changed file. Of the 19 fine-tuned replies,
4 use that format and all 4 compile; 15 answer with a single bare fenced
block, which
[`parse_generated_files`](../../eval/generate.py) maps onto the sample's
target path. Every ada-eval target path is a spec (`.ads`) file, and 6 of
those 15 replies open with `package body`, so the overlay writes a package
body into a package spec and GNAT rejects the project. Those 6 are exactly
the body-only failures; the other 3 are ordinary compile errors. The base
model emitted the requested format on all 19.

So the 568 new `spark_verified` turns bought prover-shaped Ada and cost the
multi-file reply shape the harness parses. The blocker count did not fall,
so the expectation stated above is not met. Two fixes, in order of cost:
train on `File:`-headed answers (the parse contract is a prompt requirement,
so the curriculum should carry it), or teach the harness to route a
`package body` reply to the sibling `.adb`. Neither is done here.
