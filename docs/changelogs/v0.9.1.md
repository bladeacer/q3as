# Changelog v0.9.1

Not the whole log: see the [changelog index](index.md) for every version and
the [results index](../results/README.md) for the measured numbers.

This version switches the default training base to Unsloth's pre-quantized
4-bit Qwen3-8B, makes the fine-tuning setup model agnostic for five candidate
models, and publishes a support table that states plainly that none of them has
been run on the reference machine yet. No data source was added and the dataset
is unchanged; the [v0.10.0 scope](../../plan.md) still stands.

## Pre-quantized 4-bit base by default

`make download` now fetches
[`unsloth/Qwen3-8B-unsloth-bnb-4bit`](https://huggingface.co/unsloth/Qwen3-8B-unsloth-bnb-4bit)
into `models/qwen3-8b` instead of the 16 GB BF16
[`Qwen/Qwen3-8B`](https://huggingface.co/Qwen/Qwen3-8B). The repo is about
7.5 GB on disk and keeps QLoRA training near 5-6 GB of VRAM. The local path is
unchanged so generation labels (`base_qwen3-8b`) and the eval wiring keep their
shape; only the bytes behind that path changed.

The downloader's completeness check was wrong for this layout: it demanded
`configuration.json`, `special_tokens_map.json` and a sharded index, none of
which every candidate ships. It now requires `config.json`,
`tokenizer.json`, and `tokenizer_config.json`, plus one of a sharded index, a
single `model.safetensors`, or numbered shards, and it verifies the referenced
shards exist. The light sanity check uses the same helper, so a model that
passes the download check also passes verification.

## Model registry and support table

[`training/model_registry.py`](../../training/model_registry.py) is now the
single source for the official repo, the repo training loads, the local cache
directory, the loader backend, LoRA settings, packing, and the `tested` flag.
Five models are registered: Qwen 3 8B, Qwen 3.5 4B, Spark-X2.6-4B, K2 Horizon
7B, and LFM 2.5 2.6B. `make model-table` prints the table from the registry;
the same content is published in [docs/models.md](../models.md) and linked from
the [docs index](../README.md) and the project README.

**Every row says Tested = No.** That includes the new default: the earlier
configuration trained on the original BF16 weights, so it is not evidence that
the 4-bit base, packing, or any of the four new models works on this hardware.
Official repositories were looked up on Hugging Face for the table, and the
architecture notes record what the lookup found: Qwen3.5-4B is a multimodal
hybrid with no verified Unsloth bnb-4bit mirror; Spark and K2 ship custom
`modeling_*.py`; K2 has 9.0B actual parameters despite the 7B name; LFM2 uses
hybrid convolution/attention layers and a non-Apache license. The support
column describes what the loader is expected to do, not a measured result.

## Model-agnostic training

`--model <key>` (or `MODEL=<key>` for make) selects the whole configuration.
Explicit flags still win: `--model-name`, `--cache-dir`, `--backend`,
`--packing`, `--packing-strategy`, `--offload-embedding`,
`--trust-remote-code`, and `--max-seq-length` can all override the registry.
`--lora-rank`, `--lora-alpha`, and `--max-seq-length` now default to the
registry value for the chosen model; K2 Horizon therefore gets rank 16.

Two backends are supported. `unsloth` uses `FastLanguageModel` with
`offload_embedding=True` when the installed version accepts the argument and
falls back with a warning when it does not. `hf` uses transformers + PEFT with
4-bit bitsandbytes and `adamw_8bit` for custom-code and hybrid models; it saves
the adapter only, because a 4-bit base cannot be merged in place on an 8 GB
card and `eval/generate.py` already loads adapter + base. The registry selects
the backend, and `--backend` overrides it. The chunked evaluation resolves
`lm_head` through a helper that also handles wrapped and multimodal models,
with a clear error instead of an opaque `AttributeError` when an architecture
is not covered.

`make download-models` fetches all registered models, skipping complete
caches; `make check-models` checks every cache and downloads only what is
missing. `make all` still fetches only the selected model, so a normal run does
not acquire ~30 GB of weights it will not use.

## Packing is now on, with a safe default strategy

An earlier measurement on this host found that Unsloth's `bfd` packing needs a
FlashAttention varlen path the box does not have, so the previous documentation
concluded packing was not applicable. That conclusion is reversed here: packing
is on by default because it packs several short Ada snippets into one 1024-token
row, but the default strategy is `wrapped` (a flat row of EOS-delimited
records), which does not need that path. `--packing-strategy bfd` remains available for hardware
that supports it, with a warning about cross-record attention otherwise.
`--no-packing` restores the old one-record-per-row behaviour. LFM 2.5 keeps
packing off in the registry until convolution boundaries are verified.
The eval splits are never packed; the chunked callback still scores them as
text.

## Tests: 584 -> 600 (expected)

[`tests/test_model_registry.py`](../../tests/test_model_registry.py) pins the
five keys, unique official/training repos, HTTPS URLs, per-model VRAM settings,
CLI output, and override precedence. Download tests cover the unsloth layout
without `configuration.json`, the single-file layout, missing shards, and the
explicit repo/path overrides. Trainer tests cover registry defaults and flag
overrides for packing, backend, offload, and rank. Existing train and Makefile
tests still pass with the new `--model` argument in the pipeline.

## Publishing

`make bump-version PART=patch` moved 0.9.0 to 0.9.1 across
[`alire.toml`](../../alire.toml), `alire-dev.toml`, `alire-ast.toml` and
[`pyproject.toml`](../../pyproject.toml); two tests in
[`tests/test_reporting.py`](../../tests/test_reporting.py) fail if those ever
disagree. No result file is linked: no model was trained for this version, so
there is nothing to measure.
